# 失败模式：Shell 扩展 DLL 被资源管理器加载 → 目录**删不掉**（不是权限问题）

| 字段 | 值 |
|---|---|
| **验证情况** | 已证实（连续多次删除失败，改为重命名一次成功） |
| **适用** | Windows；目标是**曾安装过的软件**的数据/程序目录，且该软件注册了 Shell 扩展 |
| **实例** | 某办公软件的 `%LOCALAPPDATA%` 子目录，残留 5 个 DLL |
| **环境** | DSH `0.2.0-rc.2`，Windows 11 |
| **发现日期** | 2026-10-10 |
| **复核方式** | 见"复现方法" |

---

## 症状

用 `shutil.rmtree` / `Remove-Item -Recurse -Force` 删目录时：

- 大部分文件删掉了，**只剩几个**怎么都删不掉
- **没有权限错误提示**（用 `ignore_errors=True` 时完全静默）
- 反复重试结果一样；清只读属性、多轮循环删除，**都无效**

实测残留文件名里有明确线索：

```
<厂商>shellext64.dll
<厂商>shellext64.dll
```

**`shellext` 就是答案。**

## 根因

**Shell 扩展**（右键菜单、缩略图、属性页处理器）由 `explorer.exe` **加载进自己的进程**。
DLL 一经加载即被占用，**直到资源管理器重启或系统重启**才释放。

所以会出现：**进程列表里没有该软件的任何进程，文件依然删不掉** ——
这正是最容易误判为"权限问题"的地方。

## 处置：不要硬删，改成"重命名让位"

重命名只需改目录项，**不触碰被锁文件的内容**，通常能成功：

```python
os.rename(src, src + ".old-" + 时间戳)      # 整个目录改名
```

改名成功后原路径即空出。若真实目的是"在原位置放别的东西"
（比如一个指向其它盘的目录联接），**可以直接继续**：

```
cmd /c mklink /J <原路径> <目标路径>
```

残渣留着不影响使用；**下次重启后它就是普通目录，随手删掉即可**。

## 反例 / 易混淆点

- **不是权限问题**：所有者/ACL 正常，只读属性也清了，一样删不掉。
- **不是杀毒软件误报**：进程列表里没有任何相关进程。
- **不要反复重试**：占用是持续的，重试无意义。
- **记住解锁时机**：`explorer.exe` 重启或系统重启后锁自动消失。

## 时效性警告

无（这是 Windows 加载器的固有行为，短期不会变）。
