# 失败模式：DSH 的探测工具数据源不一致

| 字段 | 值 |
|---|---|
| **验证情况** | 已证实（同一时刻同一 entry 拿到矛盾结果） |
| **适用版本** | DSH `0.2.0-rc.2`，desktop profile |
| **发现日期** | 2026-10-06 |

---

## 症状

同一个插件条目，两个官方工具给出**互相矛盾**的答案：

| 工具 | 对 `dsh-plugin-ops-bundle` 的报告 |
|---|---|
| `cordis_inspect_query` → `provider=Config, method=listConfigs` | `status: "absent"`（不存在） |
| `plugin_manager` → `action=list_plugins` | `enabled: true`, `fiberPhase: "active"` |

## 根因

**两个工具读的不是同一份数据：**

- **`Config`（cordis inspect）读的是「会话启动时拍的快照」** ——
  会话开始后才新增的条目，在快照里永远不存在，因此报 `absent`。
- **`plugin_manager` 读的是「当前实时状态」**。

## 后果（这个坑很实际）

**新加的插件用 `Config` 查永远显示 `absent`**，容易被误判成"没装上 / 路径错了"，
进而去反复改配置 —— 而实际上配置完全正确。

## 处置

| 想知道的 | 该用哪个工具 | 关键字段 |
|---|---|---|
| 插件**当前是否真的在跑** | `plugin_manager action=list_plugins` | **`fiberPhase`**（`active` / `null`） |
| 插件**是否注册了服务** | `cordis_inspect_query provider=Service method=listService` | 报 `no catalogued Service named X` 即未注册 |
| 模型**是否有该工具** | `cordis_inspect_query provider=Tool method=listTools` | 看 tools 数组 |
| 某条目的 **Config schema** | `Config listConfigs`（快照够用，schema 不随会话变） | `schema` |

**判定规则：凡涉及"改动有没有生效"，一律用 `plugin_manager`；`Config` 只用来读 schema。**

## 另一个相关陷阱：`fiberPhase: active` ≠ 服务已注册

实测：`dsh-ops-bundle` 报 `fiberPhase: active`，但它的服务 `dshOps`
在 `Service listService` 里**查不到**。

⇒ `fiberPhase` 只表示"插件被实例化并运行"，**不保证它成功注册了服务**。
要确认功能可用，必须**分别查 Service / Tool**。

## 相关线索

`fiberPhase` 这个字符串只出现在
`@deepseek-ai/dsh-tool-cordis\lib\types\api-catalog.js`，
说明它是 cordis inspector 的**投影字段**，不是插件本身的状态。

## 复现方法

```
# 同一时刻对同一 entry 取两个数据源，观察差异
plugin_manager action=list_plugins offset=<n> limit=<m>
cordis_inspect_query platform=host provider=Config method=listConfigs
  input={"entry":"include:<patchId>"}
```

## 时效性警告

若未来 `Config` 改为实时读取，本文件失效。
**复核方式**：新增一个条目后立刻用两个工具查，看是否还矛盾。
