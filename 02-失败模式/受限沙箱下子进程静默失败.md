# 失败模式：受限沙箱下调用外部程序会**静默失败**（不报错，只是没有输出）

| 字段 | 值 |
|---|---|
| **验证情况** | 已证实（同一脚本、同一命令，两种模式下输出相差约 1700 倍） |
| **适用** | Windows + DSH 受限文件策略；用 Python / Node 之类**转调**外部程序的场景 |
| **实例** | `subprocess.call(["tasklist"], stdout=文件)` |
| **环境** | DSH `0.2.0-rc.2`，Python 3.14 |
| **发现日期** | 2026-10-10 |
| **复核方式** | 见"复现方法" |

---

## 症状

一段脚本通过 `subprocess` 调外部命令、把输出重定向到文件，结果：

- **脚本正常退出**（exit code 0）
- **脚本自己的 print 正常输出**
- 但**外部命令的输出文件是空的**，或只有几十字节的错误信息

实测对照：

| 运行模式 | 输出文件大小 |
|---|---|
| 受限模式（默认 workspace-write） | **17 字节** |
| 放宽模式（danger-full-access） | **29252 字节** |

因为脚本本身不报错，极易被误读成"环境里本来就没有那个进程/文件"——
**这是本条最坑的地方**，会直接导致错误结论。

## 根因

受限令牌下无法创建子进程所需的管道/句柄。这与"Node.js 用默认 `stdio: 'pipe'` 的
`spawn` 报 EPERM"属于同一类边界，但 Python 的表现更隐蔽：**不抛异常，只是拿不到输出**。

值得强调：**纯文件系统操作不受影响**。同一受限模式下，用 `os.scandir` / `os.walk`
遍历几十万文件完全正常。所以"受限模式下 Python 干不了活"是错的，
准确边界是 **"不能调外部程序"**。

## 处置

需要转调外部程序（`tasklist` / `robocopy` / `mklink` / `setx` …）时，
**把这一条命令显式申请放宽**（一次性审批），不要在受限模式下绕。

同时脚本里**不要用"输出为空"推断"没有结果"**，加一条自检：

```python
out, rc = run_capture(["tasklist", ...])
if len(out) < 100:                        # 正常输出不可能这么短
    raise SystemExit("capture failed - likely confined sandbox")
```

## 反例 / 易混淆点

- **不是命令不存在**：同一个 `tasklist` 在放宽模式下立刻成功。
- **不是"受限模式什么都不行"**：文件扫描、读写、统计都正常，只有跨进程调用受限。
- **不要靠重试解决**：受限是确定性的，重试结果一样。

## 时效性警告

若 DSH 改为在受限模式下禁止子进程时**显式报错**，本条的可读性问题即缓解
（故障仍在，但至少不再静默）。
