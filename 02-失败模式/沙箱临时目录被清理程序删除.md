# 失败模式：会话临时目录被第三方清理程序删除 → 该会话**所有** shell 命令失效

| 字段 | 值 |
|---|---|
| **验证情况** | 已证实（同一会话内两次复发；每次重建目录后立即恢复；清理源已定位） |
| **适用** | Windows + DSH 受限文件策略；机器上装有"垃圾清理"类软件或开启了系统存储感知 |
| **实例** | 会话临时目录 `%TEMP%\dsh-<8位随机串>` |
| **环境** | DSH `0.2.0-rc.2`，Windows 11 |
| **发现日期** | 2026-10-10 |
| **复核方式** | 见"复现方法" |

---

## 症状

会话中途开始，**所有** `pwsh` 调用失败，报错形如：

```
Error: sandbox mode "workspace-write" is requested but no sandbox backend is usable on this host;
refusing to run the command unconfined.
Runner failure: windows-acl-run: --temp is not an existing directory:
C:\Users\<用户>\AppData\Local\Temp\dsh-rSQyeG
```

关键特征：

- 报错发生在**沙箱准备阶段**，不是被执行的命令本身 —— 换命令、简化命令都没用
- 报错里给出一个**只属于本次会话的目录**（形如 `dsh-<8位随机串>`）
- 同一会话里这个路径**始终不变**（DSH 在会话启动时创建一次并缓存）
- **放宽到 full-access 仍能运行**（那条路径不需要沙箱）——这是最大的迷惑点

## 根因

DSH 在**会话启动时**于 `%TEMP%` 下创建一个随机会话目录供受限沙箱 runner 使用，并在全程复用。

第三方清理程序把 `%TEMP%` 内容当垃圾清掉后，**目录消失、DSH 仍缓存着该路径**，
于是本会话**每一个**受限命令都会在启动前失败。

实测旁证：同一次故障中，同一段脚本在受限模式写出的输出文件只有 **17 字节**
（一句错误信息），而在完全权限下写出 **29252 字节**（正常进程列表）。

## 处置：重建那个目录（一步）

用**文件工具**（不是 shell）在报错给出的路径下建一个占位文件即可 ——
文件工具走另一套后端，不受该故障影响：

```
write  <报错里的目录>\_keepalive.txt   内容随意
```

建好后**立即**重跑刚才失败的受限命令，即恢复。

> 注意：若该路径之前建过占位文件、后来又被清理，写工具可能因
> "文件已不存在"的观察策略而拒绝；**换一个新文件名**（如 `_keepalive2.txt`）即可绕过。

## 预防：把 TEMP 移出系统盘

清理程序盯的是系统盘的临时目录，最彻底的办法是改用户级 `TEMP`/`TMP`：

```powershell
setx TEMP "E:\Temp"
setx TMP  "E:\Temp"
```

- **不需要管理员**（只改 `HKCU\Environment`）
- **已运行的进程不受影响**：DSH 必须**重启**才用上新值
- 回滚：把两个值改回 `%USERPROFILE%\AppData\Local\Temp`
- 附带好处：临时文件不再占用系统盘

## 反例 / 易混淆点

- **不是"命令写错了"**：报错在命令启动前，任何命令都一样。
- **不是"工作区缺 WRITE_OWNER"那一条**：那条的报错是 `SetNamedSecurityInfoW failed`，
  本条是 `--temp is not an existing directory`，病灶完全不同。
- **不要因此长期开全权**：只是一次目录丢失，重建即可。
- **通常不是 DSH 自己清的**：会话期间 DSH 不会删它；实测为外部清理程序所为。

## 时效性警告

若 DSH 改为"每次命令现场创建 temp"或"目录丢失时自动重建"，本条即失效。
复核方式：手动作废那个 `dsh-*` 目录，看下一条受限命令是否失败。
