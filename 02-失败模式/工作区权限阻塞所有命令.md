# 失败模式：工作区目录缺 `WRITE_OWNER`，该工作区下**所有命令**都跑不了

| 字段 | 值 |
|---|---|
| **证据等级** | 已证实（修复前/后各一次实测；修复后受限模式恢复正常） |
| **适用** | Windows + DSH 受限文件策略；工作区位于非系统盘根时更易命中 |
| **实例** | 工作区 `E:\git` |
| **环境** | DSH `0.2.0-rc.2` |
| **发现日期** | 2026-10-06 |
| **复核方式** | 见"复现方法" |

---

## 症状

把会话工作区设到 `E:\git` 后，**任何** `pwsh` 调用都立即失败——连只读的列目录也一样：

```
Error: SetNamedSecurityInfoW failed (Win32 5): grantWrite(E:\git)
```

注意失败的是 **DSH 给工作区授写权限这一步**，不是被执行的命令本身。
所以"换一条命令再试"毫无意义——命令根本没启动，连 `exit code` 都不存在。

## 根因

DSH 在启动受限命令前会尝试给工作区目录补一条写权限。这一步要求调用方对该目录
同时持有 `WRITE_DAC` **和** `WRITE_OWNER`。实测该目录：

```
OBJECT=E:\git READABLE=True
  OWNER=S-1-5-21-...-1001 IS_CURRENT_USER=True
  WRITE_DAC=True  WRITE_OWNER=False          ← 缺的是这个
```

父目录 `E:\` 归 `S-1-5-18`（SYSTEM）所有、当前用户没有 `WRITE_DAC`，
因此**不能**靠"改父目录让子目录继承"来修。

## 处置：用 DSH 自带 skill `diagnose-windows-sandbox-acl` 一条命令修复

该 skill 就在 skill catalog 里。它的脚本**没有模式参数**，一次调用完成
诊断 + 备份 + 修复 + 验证：

```powershell
& '<skill目录>\scripts\diagnose-windows-sandbox-acl.ps1' `
     -Path 'E:\git' -AllowRoot 'E:\git' -Out 'E:\DSH-Archive\acl-recovery-<日期>'
```

要点：

- **必须在放宽模式下跑**（`danger-full-access`，一次性审批）。受限令牌自己改不了权限；
  在受限模式跑它只会把沙箱自身的限制误报成"缺权限"。
- `-Out` 要放在**持久的用户目录**（脚本会写备份 + 独立回滚脚本），
  不要用 skill 资源目录（skill 卸载即删）。
- 只放宽这**一条**命令，不要长期把会话开成全权。

修复的验证输出（同一次运行内给出）：

```
GRANTED E:\git SID=S-1-5-21-...-1001
verification: grant  status=verified
  before={writeDac:true, writeOwner:false}
  after ={writeDac:true, writeOwner:true}
RECAP {..., "verifications":[{"operation":"grant","status":"verified"}]}
```

`nextAction=verify_original_confined_operation` → **回到受限模式重跑原来失败的操作**，
即可确认真的修好了（修复通过验证不等于原操作一定恢复，必须重跑一次）。

## 回滚

脚本在改动前就写好备份与独立回滚脚本，命令在输出里以 `ROLLBACK` 行给出：

```
pwsh -NoProfile -File '<Out>\acl-backup-<id>.json.ps1' `
     -Path 'E:\git' -AllowRoot 'E:\git' -Restore '<Out>\acl-backup-<id>.json'
```

## 反例 / 易混淆点

- **不是"命令写错了"**：报错发生在命令启动前，任何命令（含 `Get-ChildItem`）都一样。
- **不是工作区不存在**：目录存在、可读、归当前用户所有。
- **"受限模式本来就该拒绝写工作区之外"不算本条**：那是**预期**行为；
  本条是**工作区自身**的写入都无法provision，且连只读命令都起不来。
- **不要手工改权限、不要动父目录、不要提权运行**：skill 脚本已覆盖正确做法，
  手工改容易漏掉备份与验证。

## 时效性警告

若 DSH 改为"无法授写时降级运行"而非直接拒绝执行，本条即失效。
复核方式：挑一个非系统盘根下的目录作工作区，看是否复现同一报错。
