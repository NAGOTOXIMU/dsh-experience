> **给 AI 用**：这是"照做就行"的清单。每条都标了**为什么**和**怎么验证**。

## A. 环境类

### A1. 把 shell 从 PowerShell 5.1 换成 7 —— **单项收益最大**
- **为什么**：5.1 有三类反复咬人的坑（无 BOM 中文脚本报假语法错误 / 引号被拆 / 外部命令 UTF-16 输出乱码）
- **怎么做**：`winget install Microsoft.PowerShell`（MSIX，per-user，**免管理员**）
- **注意**：**必须重启 DSH 客户端**才生效（shell 在启动时解析）
- **验证**：`$PSVersionTable.PSVersion` 应为 7.x
- **回退**：`winget uninstall Microsoft.PowerShell`

### A2. 装齐命令行工具链
```powershell
winget install BurntSushi.ripgrep.MSVC   # rg
winget install sharkdp.fd                # fd
winget install jqlang.jq                 # jq
winget install MikeFarah.yq              # yq
winget install SQLite.SQLite             # sqlite3
```
- **为什么**：这些是"给 agent 装的手脚" —— 没有它们就只能人肉点界面
- **验证**：逐个 `Get-Command <名字>`；**存在 ≠ 可用**，要真的跑一次

### A3. `gh` 登录
```powershell
gh auth login    # scope 至少要有 repo
gh auth status   # 验证
```
- **为什么**：这是"手动开网页查资料"与"agent 自己查"的分界线
- **额外好处**：`gh` 是 Go 写的、**不碰 Windows 凭据存储**，所以在受限沙箱里也能用（而同场景 `git push` 会失败）

## B. 配置类（**最容易把应用改坏，风险最高**）

### B1. 改 `cordis.patch.yml` / `workspace.json` 的标准流程

1. **备份**（带时间戳，目标放在应用读不到的位置）
   ```powershell
   Copy-Item <目标文件> "$<备份目录>\<文件名>.bak-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
   ```
2. **改** —— 优先用**会校验语法的工具**改，而不是肉眼手写：
   - JSON：让 Python `json.dump` 生成（**保证格式合法**），再写回
   - YAML：注意**不要用 tab 缩进**，`patch` 是**整行替换**语义（不是合并）
3. **立刻校验**：
   ```powershell
   # JSON
   Get-Content <文件> -Raw -Encoding utf8 | ConvertFrom-Json | Out-Null
   # YAML
   yq e '.' <文件> | Out-Null
   ```
4. **验证内容**（不是只看"没报错"）：逐条核对关键字段 + `Test-Path` 所有路径
5. **重启后按时间戳确认真的被加载**：
   ```powershell
   (Get-Item <配置文件>).LastWriteTime   # 应早于
   (Get-Process -Name 'DeepSeek Harness' | Sort StartTime | Select -First 1).StartTime
   ```

- **为什么这么麻烦**：这两个文件写坏 → **应用直接起不来**，而报错信息往往没有指向性

### B2. 判断"我改的东西生效了没有"（三条硬规则）
1. **配置 ≠ 运行态** —— 配置是**启动时读一次**的快照；判断运行态必须用运行时探测
2. **两个工具给出不一致时，以"实时"那个为准**（例：`Config` 是快照，`plugin_manager` 是实时）
3. **插件的真实状态看 `fiberPhase`**（`active` = 已实例化；`null` = 未实例化），**`enabled` 字段不可靠**

## C. 目录类

### C1. 移动/归类目录的标准流程
1. **先记基线**：每个目录的**文件数 + 总大小**
2. **同盘移动**（只是改目录项，秒完成，不复制数据）
3. **移动后逐项校验**：文件数与基线**必须一致**，不一致立刻回退
4. **旧路径留 junction 指回新位置**：
   ```powershell
   New-Item -ItemType Junction -Path '<旧路径>' -Target '<新路径>'
   ```
   - **为什么**：历史会话记录的 `cwd` 是旧路径 → **junction 没了那些会话就打不开**
5. **改了路径的引用要同步更新**（配置文件里的 `path`、`node_modules` 里的 junction…）

### C2. 给"装在工作区里的程序"打显式完整性标签
```powershell
icacls '<应用目录>' /setintegritylevel (OI)(CI)M /T
```
- **什么时候用**：目录被标了 `Low Mandatory Level`，导致里面程序起不来（典型症状：秒退、`0x80000003`、零日志）
- **为什么有效**：**显式**标签能顶住父目录的 Low 继承，之后父目录怎么变都不受影响（已实测）
- **成本**：实测 12 秒 / **无需管理员** / 可逆
- **顺带**：这**不解决"工作区被设 Low"这件事本身**，只是给应用目录加了豁免 —— 根治要避免"工作区 = 安装目录"

## D. 仓库类

### D1. 建仓库并推送（注意沙箱限制）
1. **把仓库放在会话工作区内** —— 这样 `git init/commit/push` **全程不需要额外权限**（已实证）
2. 代理要设（端口会变，**别硬编码**）：
   ```powershell
   $sys = (Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings').ProxyServer
   $env:HTTP_PROXY = "http://$sys"; $env:HTTPS_PROXY = "http://$sys"
   ```
3. **中文路径的 git 调用一律带 `-c core.quotepath=false`**，否则路径被转义成八进制、`update-index` 之类会失败

### D2. 三个仓库的职责分工（**别混用**）
| 仓库 | 放什么 | 本地 |
|---|---|---|
| archive | 一次性产物 | 推送后**删本地** |
| experience | 经验正文（本库） | **保留** |
| refit | 改装快照（配置+记忆+skills+工具+**自研插件源码**） | 保留 |

- ⚠️ **自研插件必须连源码一起备份** —— 它们不在 npm 上，只记录包名是**装不回来的**

## E. Agent 效率类

### E1. 改工作区之外的**文件**时，用**文件工具**而不是 `pwsh`
- **为什么**：`pwsh` 子进程**只能写工作区**（与文件策略无关）；而 `read`/`write`/`edit` 遵循文件策略，完全权限下能写任意位置
- **代价对比**：`pwsh` 试一次就会被拒（浪费一轮）；文件工具直接成功

### E2. 给 agent 写小工具时，坚持两条
1. **argv 数组进、结构化结果出**（绝不拼 shell 字符串）
2. **编码与退出码由工具兜底**（自动识别 UTF-8 BOM / UTF-16 / 裸 UTF-16LE / GBK）

### E3. 让子进程自己处理"人的界面"
凡是"打开网页 / 点按钮 / 看界面"的操作，优先找 CLI 替代（`gh`、`rg`、`fd`、`jq`、`sqlite3`…）
