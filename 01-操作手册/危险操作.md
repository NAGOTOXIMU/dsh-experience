# ⚠️ 危险操作手册（会导致问题 / 已经踩过的）

> **给 AI 用**：动手前扫一眼这一页。如果你要做的事在表里，**先停**，改走"正确替代做法"。
> 每条都写着"为什么会出事"——不是迷信，是实测。

---

## ❌ D1. 把「会话工作区」设成 DSH 的安装目录

| | |
|---|---|
| **后果** | DSH 会把工作区设成**低完整性**，标签沿 NTFS 继承污染整棵树 → 装在里面的 Electron 应用（**包括 DSH 桌面端自己**）**双击无反应、秒退、零日志**，退出码 `0x80000003` |
| **为什么难查** | 不产生崩溃日志、不建 user-data、系统事件里也没有记录，看起来像"应用坏了" |
| **正确做法** | 工作区与"装着可执行程序的目录"**必须分开**；已经中招就 `icacls '<应用目录>' /setintegritylevel (OI)(CI)M /T` |

---

## ❌ D2. 用 `icacls` 修「会话工作区」的权限（**最反直觉的一条**）

| | |
|---|---|
| **为什么会出事** | 工作区 ACL **坏**的时候，DSH 授权**失败** → 低完整性标签**设不上** → 一切正常；<br>你**修好** ACL 之后，DSH 首次授权**成功** → 标签**立刻落到整棵树** → 装在里面的程序当场起不来 |
| **结论** | **"修好权限"这个动作本身可能就是引爆器** |
| **正确做法** | 修完 ACL **务必立刻复查**：`icacls '<工作区>' \| Select-String 'Mandatory Label'`；<br>以及提前给应用目录设显式 Medium（见安全操作 C2） |

---

## ❌ D3. 同时装两个 DSH 桌面客户端

| | |
|---|---|
| **后果** | 不同产品名的客户端可能**共用同一个 user-data 目录与端口** → `requestSingleInstanceLock()` 互斥 → **后启动的连窗口都不出现** |
| **判别** | 窗口都没有 = userData 单实例锁；窗口出来但提示"有其他正在运行的 DSH" = 端口 `EADDRINUSE` |
| **正确做法** | 只留一个；卸载旧的那个（electron-builder/NSIS 装的可用注册表里的 `QuietUninstallString` 静默卸载） |

---

## ❌ D4. 往 patch 里加"纯 host 插件"（不声明 `dsh.client`）

| | |
|---|---|
| **后果** | 轻则不激活（白装）；**重则直接启动失败** —— 旧版客户端把插件的 `pending` 判为致命错误（`web boot: N entry did not activate`） |
| **典型陷阱** | `@ningbainb` 三件套（user-scope / memory / personal-prompt）：个人提示那个会**永久 pending** 等 `settingsScope` 服务 |
| **正确做法** | 装之前先跑三层判据（见 `02-失败模式/插件装了不激活.md`）；**记忆功能用 `@jipika/dsh-memory`** |

---

## ❌ D5. 改配置不备份 / 手写 JSON

| | |
|---|---|
| **后果** | `cordis.patch.yml`、`workspace.json` 写坏 → **应用直接起不来**，且报错没有指向性 |
| **正确做法** | 备份 → 让 Python `json.dump` 之类的**保证格式合法** → 立刻 `ConvertFrom-Json` 校验 → 重启后按时间戳确认加载 |

---

## ❌ D6. 用 `pwsh` 去写工作区之外的文件

| | |
|---|---|
| **后果** | 必然 `UnauthorizedAccessException`（**与文件策略无关**，完全权限也不解锁）→ 白跑一轮 |
| **正确做法** | 改用**文件工具**（`write` / `edit`），它们遵循文件策略 |

---

## ❌ D7. 在受限沙箱里做这些事

| 操作 | 结果 | 替代 |
|---|---|---|
| `git push`（推送需要写 `.git` 的仓库） | 失败（schannel 取不到凭证 / 命名管道被拒） | 让用户在其普通终端里跑；或用 `gh api` 走 HTTPS |
| `curl.exe` 发 HTTPS | `SEC_E_NO_CREDENTIALS`（受限令牌碰不到 Windows 凭据存储） | 用 Node.js / `gh`（自带 TLS 实现） |
| `Get-NetTCPConnection` | `CimException - 拒绝访问`；**配了 `-ErrorAction SilentlyContinue` 会被静默吞成空输出**，看起来像"端口没监听" | 用原生 `netstat -ano` |

---

## ❌ D8. 反复重跑同一个失败的修复脚本

| | |
|---|---|
| **后果** | 同一个障碍反复试，白烧 token（"变形重试也算重试"） |
| **正确做法** | 同一工具同参数连续 3 次失败 / 同命令连续失败 2 次 / 8 步无新信息 → **停、报、换假设**；同一障碍**最多 3 种方案** |

---

## ❌ D9. 用 `Select-Object -First N` 截断子进程的输出

| | |
|---|---|
| **后果** | 读端提前关闭 → 子进程 BrokenPipe → **退出码变 -1**，看起来像脚本坏了 |
| **正确做法** | 要判断退出码就别截断它的 stdout；需要看前 N 行就先重定向到文件再读 |

---

## ❌ D10. 删掉那些"看起来多余"的 junction

| | |
|---|---|
| **后果** | 旧路径兼容层没了 → **历史会话打不开**（它们的 `cwd` 记的是旧路径）；插件 junction 没了 → **插件失效** |
| **正确做法** | junction 一律当作"兼容层"保留；确需删除时先确认没有会话/插件指向它 |

---

## ❌ D11. 改插件的 `package.json` 里的 `name`

| | |
|---|---|
| **后果** | DSH 按 `name` 解析模块 → `Cannot find package` → **整棵 plugin tree 起不来** |
| **正确做法** | **目录名可以随便改**，`name` 一个字都不能动 |

---

## ❌ D12. 给 `.ps1` 写中文却不带 BOM（**只在 PS 5.1 成立**）

| | |
|---|---|
| **后果** | 5.1 按 GBK 解码 → **假语法错误**（`字符串缺少终止符`），让人以为脚本写坏了 |
| **现状** | 换到 PowerShell 7 后**这个坑消失**（实测无 BOM 的中文脚本正常运行） |
| **正确做法** | 仍**顺手带 BOM** —— 因为脚本可能被别的 5.1 环境调用（用户双击、`powershell -File`） |
