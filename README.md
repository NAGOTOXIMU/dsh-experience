# DSH 调试经验库

> **这是什么**：把每次与用户协作中得到的**可复用经验**沉淀下来，供以后调试其他 harness、
> 或帮助别人配装 DSH 时直接取用。
> **性质**：私有仓库。可随时改为公开，或把单篇摘出来发给别人。
> **起点**：2026-10-06（DSH `0.2.0-rc.2` 时期）

---

## 为什么要有这个库

官方发布的 DSH 仍是 preview 形态，很多机制**没有文档、也没有稳定保证**。
真实经验主要来自"踩一遍才知道"。这些经验如果不落盘，就会随会话消失，
下次（或别人）还得重踩一遍。

这个库的目标是让经验**可检索、可复用、可传递**。

---

## 第一原则：每条经验都必须标证据等级

**这是本库最重要的规则。**

AI 助手在这个领域会大量产生"看起来合理但没验证"的判断 —— 本项目本身就在
同一次协作里出现过 **5 次错误结论**（见 `04-自省/`）。若把那些直接写成"经验"，
会污染整库、误导后来者。

因此每条经验**必须**带：

| 字段 | 取值 | 含义 |
|---|---|---|
| **证据等级** | `已证实` | 有可复现的实测输出（命令 + 结果） |
| | `已推翻` | 曾被当作结论，后经实测否定 —— **也很有价值，别删** |
| | `未证实` | 合理推测，尚无证据 |
| **适用版本** | 如 `DSH 0.2.0-rc.2` | DSH 迭代快，脱离版本的经验会失效 |
| **时效性** | 复核方式 | 怎么快速验证这条还成不成立 |

**没有证据等级的条目，一律视为噪音。**

## 目录结构

```
dsh-experience/
├─ README.md              # 本文件：索引与维护约定
├─ 00-总览/
│  └─ DSH-架构与调试入门.md   # 给"第一次接触 DSH 的人"的导览
├─ 01-任务记录/            # 每次协作的结构化记录（按日期）
├─ 02-失败模式/            # 症状 → 根因 → 处置（最实用的一类）
├─ 03-可复用工作流/        # 可直接照做的流程
├─ 04-自省/               # 助手的误判与教训（防止重复犯错）
└─ 05-交互准则/            # 用户偏好 / 沟通方式
```

## 各部分怎么写

### 01-任务记录：`<任务名>-<YYYYMMDD>.md`

一次协作一篇。回答三个问题：

1. **用户想要什么**（原话层面的诉求，不是我的转述）
2. **发生了什么**（做了什么、结果如何、验证证据）
3. **留下了什么**（可复用的结论指向哪个失败模式/工作流文件）

### 02-失败模式：`<症状关键词>.md`

**最值得写的一类。** 结构固定：

```
症状：用户/助手看到的现象
根因：真正的原因
证据：可复现的命令与输出
处置：怎么修；修不了的怎么说
反例：哪些看似同类其实不同
```

### 04-自省：`<主题>.md`

如实记录我判断错的地方。**这类文档的价值不低于技术文档**，因为：
- 它标出了"我的直觉在哪些地方不可靠"
- 它是防止同类错误重演的唯一手段

## 维护约定

1. **每次协作结束**：写一篇 `01-任务记录/`，并把其中可复用部分抽成
   `02-` / `03-` 的独立文件。
2. **发现被推翻的结论**：不要删，改标 `已推翻` 并写清"当初为什么错、怎么发现的"。
3. **不写**：涉及凭据、token、私钥、用户隐私路径的内容。
4. **写清版本**：每条结论标注验证时的 DSH 版本。
5. **本地副本策略**：本库内容由助手在 `E:\DSH-Archive\` 暂存后推送，
   推送成功后**清理本地暂存**（与主归档库一致的磁盘策略）。
