# DSH 调试经验库

> **读者主要是 AI agent**（尤其是正在调试 DSH 的其他 AI）。
> 人类读当然也行，但本库的写法是为「**被检索、被引用**」优化的：结构化、带证据等级、可直接跳转。
>
> **状态：持续累积中 —— 这不是完成品。**
> 每次协作都会往里加条目；**未解决的问题**在 [`00-速查/未解决清单.md`](00-速查/未解决清单.md) **单独标注**。

**起点**：2026-10-06（DSH `0.2.0-rc.2` 时期，Windows 桌面版）

---

## 一、先读这一页（三条使用规则）

1. **先查索引，再动手**
   | 你要做的事 | 去哪查 |
   |---|---|
   | 遇到了问题 / 报错 | [`00-速查/症状索引.md`](00-速查/症状索引.md) |
   | 要做某类任务 | [`00-速查/操作索引.md`](00-速查/操作索引.md) |
   | 想知道"什么不该做" | [`01-操作手册/危险操作.md`](01-操作手册/危险操作.md) |
   | 想知道"什么该做、怎么做" | [`01-操作手册/安全操作.md`](01-操作手册/安全操作.md) |
   | 找不着头绪 | [`00-总览/Windows沙箱与令牌问题合集.md`](00-总览/Windows沙箱与令牌问题合集.md) |

2. **看证据等级**：`已证实` 可直接采信；`已推翻` 是前车之鉴（**别删**）；`未证实` 只是线索，**别当结论**。

3. **不要把"未解决"当"已解决"** —— 所有悬而未决的都集中在一页上。

## 三、证据等级（本库最重要的规矩）

| 等级 | 含义 |
|---|---|
| **已证实** | 有可复现的实测输出（命令 + 结果） |
| **已推翻** | 曾被当作结论，后经实测否定 —— **也很有价值，别删** |
| **未证实** | 合理推测，尚无证据 —— **只是线索，不是结论** |

**没有证据等级的条目，一律视为噪音。**

> 这条规则的由来：本库建立的那次协作里，同一个人（AI）就产出了 **6 个错误判断**
> （见 [`04-自省/我的六类误判.md`](04-自省/我的六类误判.md)）。
> 若把那些直接写成"经验"，会污染整库、误导后来者。

## 四、维护约定（**持续累积**，不是一次写完）

**新增**
- **遇到新问题** → 写进 `02-失败模式/`，**必标证据等级**
- **新验证过的操作** → 按 A–E 分类加进 `01-操作手册/安全操作.md`
- **新踩到的坑** → 加进 `01-操作手册/危险操作.md`（症状 / 后果 / 为什么 / 正确做法）
- **新的可复用流程** → 写进 `03-可复用工作流/`
- **每次协作** → 写一篇 `01-任务记录/<任务名>-<YYYYMMDD>.md`

**更新**
- **解决了一个悬案** → 在 `00-速查/未解决清单.md` 里把 `❌ 未解决` 改成 `✅ 已解决（日期）`，**保留原文**并指向解决它的文档
- **发现结论被推翻** → **不要删**，改标 `已推翻` 并写清"当初为什么错、怎么发现的"
- **索引要同步**：`00-速查/` 两张索引表是入口，加完条目记得补一行

**边界**
- **不写**：凭据、token、私钥、用户隐私路径
- **写清版本**：每条结论标注验证时的 DSH 版本 —— DSH 迭代快，脱离版本的经验会失效
- **标注时效性**：能给"复核方式"就给（怎么快速验证这条还成不成立）

## 六、来源与保密

- 本库为**私有仓库**，可随时改为公开，或把单篇摘出来发给别人。
- 内容全部来自真实协作，**不含**凭据 / token / 私钥 / 用户隐私路径。
- 关联仓库（职责分开，别混用）：

  - **`dsh-experience`（本库）** —— 经验正文
  - `dsh-refit` —— 改装快照（配置 + 记忆 + skills + 工具 + 自研插件源码）
