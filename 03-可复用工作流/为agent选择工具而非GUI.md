# 可复用工作流：把「给人用的操作」换成「给 agent 用的接口」

| 字段 | 值 |
|---|---|
| **验证情况** | 已证实（本机逐项落地并实测） |
| **适用** | 任何"AI agent 在 Windows 上干活"的场景，不限 DSH |
| **整理日期** | 2026-10-07 |

---

## 一条判据

> **一个操作如果在人类流程里是「打开网页 / 点按钮 / 看界面」，对 agent 就是高成本、易错、不可复现的。
> 凡是能换成命令行或结构化接口的，一律换掉。**

用户的原话（很准确）：
> "以前你得手动打开网页去搜，装了 `gh` 之后就能直接查。我希望能够将很多你的方式都使用更适合你的。"

## 已经固化的替换（本机实例）

| 人类做法 | agent 做法 | 落地物 |
|---|---|---|
| 开浏览器搜插件市场 | `gh` 搜 topic + npm registry API | `<工具目录>\gh-dsh-search.py` |
| 网页上看仓库/Issue | `gh api` / `gh repo view` / `gh repo list` | gh CLI |
| 用文件管理器翻目录 | `rg` / `fd` / `glob` / `grep` | 内置工具 + CLI |
| 用编辑器改 JSON/YAML | `jq` / `yq` / Python `json` | 已装 |
| 点开数据库客户端查表 | `sqlite3` | 已装 |
| **手敲命令、肉眼读输出** | **argv 数组进 → JSON 出** | `<工具目录>\xrun.py` |
| 用 `grep` 刷打包二进制（asar） | 专用 peek 工具，带上下文与偏移 | `<工具目录>\asar-peek.py` |
| 手动解压/压缩包 | `7z` | `<工具目录>\7-Zip\7z.exe` |

## 三条设计原则（做新工具时照这个来）

1. **argv 数组进、结构化结果出** —— 绝不让 agent 拼 shell 字符串
   （引号、转义、空格路径，每一处都是踩过的坑）
2. **编码与退出码由工具兜底** —— 别让 agent 每次都自己处理 UTF-16 / GBK / BOM
   （`xrun.py` 的 `smart_decode` 就是干这个的：UTF-8 BOM → UTF-16 BOM → 裸 UTF-16LE 启发式 → UTF-8 → GBK）
3. **把"每次都要重新想一遍"的坑固化成脚本**
   例：装 DSH 插件必须加 `--config.auto-install-peers=false`（否则 pnpm 按 peer 去装旧版包而失败）

## 判据：什么时候该做替换

三个问题都答"是" → 直接做成 CLI / 脚本：

- 这个操作**每周做超过一次**吗？
- 它的**输入输出是结构化的**（而不是"看一张图做判断"）吗？
- 它现在的流程里**有手工步骤**（开网页、点按钮、复制粘贴）吗？

## 什么**不该**换（边界同样重要）

| 情况 | 为什么 |
|---|---|
| 需要**人的判断或审美** | UI 好不好看、截图里对不对 —— agent 无法替代 |
| 真·一次性操作 | 做完就扔，做工具的成本 > 收益 |
| 需要**登录态**的网页操作 | agent 拿不到凭据，**也不应该拿**（凭据泄露风险） |

## 落地顺序建议

1. **先用现成的 CLI**（gh / rg / fd / jq / yq / sqlite3 / 7z）—— 绝大多数需求它们已覆盖
2. **不够就包一层脚本**（如 `gh-dsh-search.py`：把"搜 GitHub + 搜 npm + 判真伪"串成一条命令）
3. **再不够才写工具**（如 `xrun.py`：解决的是一个通用问题——shell 字符串不可靠）

## 验收标准

替换成功的标志：**同样的任务，调用次数下降、且不再需要肉眼判断输出格式对不对。**
