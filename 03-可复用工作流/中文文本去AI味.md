# 中文文本去 AI 味：装哪个，以及工具做不到的部分

**证据等级**：已证实（榜单端到端实测 + 本机安装与使用）
**适用**：任何支持 `SKILL.md` 的 agent；DSH 放在 `~/.dsh/skills/<名字>/SKILL.md`

---

## 结论先行

1. 有个被别人做好的**实测榜单**：[awesome-humanizer-skills](https://github.com/zhuyansen/awesome-humanizer-skills)
   ——232 个仓库按类型和安全分级，其中 26 个跑过端到端对比（同一批文本、同一个评审模型）。
2. **中文首选**：[op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)（18.9k star）。
   31 条检查点，A–E 沿自 `blader/humanizer`，F 组是中文专属。
3. **榜单最关键的一条发现**：没有哪个工具能改掉**结构**上的 AI 味。
   40 次改写里，"点题式总结"存活 26/26，"整齐的结尾"存活 28/28——工具只换词句，结构原样保留。
   👉 所以"去 AI 味"真正的活是**自己动结构**：删段末升华、拆掉总分总、别每段都点题。

## 安装（DSH）

```powershell
git clone --depth 1 https://github.com/op7418/Humanizer-zh.git "$env:USERPROFILE\.dsh\skills\humanizer-zh"
```

安全性：仓库只有 `SKILL.md`、`README.md`、`LICENSE`、`tests/`（一个结构检查脚本），
**没有 package.json、没有 postinstall、零依赖**，MIT。属于第三方 skill 里风险最低的一档。

**catalog 热更新实测（重要更正）**：装完**当轮**就进了 skill catalog——系统直接推送了含 `humanizer-zh` 的新列表，
`skill(humanizer-zh)` 立刻可加载，**不需要开新会话**。

> 这**推翻**了本机此前记录的"新增 skill 必须开新会话才进 catalog"。
> 旧结论来自 2026-10-06 的观察（`skill(grill)` 在会话内报 unknown），现在不再成立。
> 未收敛：没确认是 DSH 版本变化还是"装入方式不同"造成的差异。

## 实际最见效的中文检查点

| 检查点 | 症状 | 处理 |
|---|---|---|
| §31 套话收尾 | 每段结尾都"综上所述""让我们期待" | 删；有实际内容的总结才留 |
| §4 起跑式铺垫 | "下面我将从三个方面展开""接下来让我们看看" | 删，直接进内容 |
| §1 假对比 | "这不只是一个 X，更是通往 Y 的入口" | 只留后半句 |
| §6 强凑三段式 | 两项内容硬凑三项、或三项内容刻意排比 | 按实际项数写 |
| §29 四字词排比 | "稳定可靠、快速响应、易于维护" | 改口语："运行稳定、响应快，也方便维护" |
| §12 AI 高频词 | 赋能、至关重要、闭环、深入探讨 | 空泛才改，术语保留 |
| §13 意义拔高 | "标志着……新时代的到来" | 删，留事实 |
| §27 进行＋动词 | "对系统进行全面测试" | "全面测试系统" |

## 别做的事

- 别把学术/商务文本强行口语化（skill 自己也强调：保留语域和正式程度）
- 别拿"字数下降"或"模型自评分"当效果证据
- 改写**不能新增事实**：数字、限定词、归因、否定、完成状态都要保留
- 别为了展示工作量去改已经通顺的句子

## 复核方式

把一段 AI 腔明显的文本喂给 skill，检查两点：① 是否只动了表达、没动结构；② 事实有没有被改、被丢。

## 未收敛

- 榜单的评测用的是"读起来像不像人写的"单一维度评分，不等于真实读者感受
- 中文工具的得分普遍不高（最高 3.0/5），说明这条路整体还比较粗
