## ❌ 未解决

### 1. 缺「运行时自省」工具（**影响面最大的一个**）

- **现象**：某些 agent preset 下，可用工具里**没有** `cordis_inspect_list` / `cordis_inspect_query` / `plugin_manager`
- **后果**：无法直接查插件的 `fiberPhase`、无法查已注册服务、无法查实时工具列表 ——
  所有"插件到底活没活"的判断只能靠**静态判据 + 推理**
- **已知线索**：`cordis.patch.yml` 里 `agent-preset-registry` 的 `selectedDefault` 指向某个 preset；
  preset 定义**不在** `~/.dsh/agents`（该路径不存在）
- **下一步**：找到 preset 定义位置，确认哪个 preset 带这三个工具，或自己写一个

### 2. 历史会话检索的「模型侧入口」

- **现状**：索引**已建成**（`~/.dsh/session-recall/index.db`，在 GUI 里按 `Ctrl+K` 搜一次即建库）；
  **但**提供模型侧 recall 工具的 `dsh-session-recall` 是**纯 host 插件、不激活**
- **后果**：**AI 自己搜不了历史会话**，只能由人在 GUI 里搜
- **下一步**：查该插件为何是纯 host（能否补上客户端半边），或找替代的检索插件

## 🤔 未证实（有推测，缺证据 —— **别当结论用**）

### 3. MSIX 版 PowerShell 7 是否在沙箱下有隐藏问题

- **事实**（已证实）：MSIX 版落在 `C:\Program Files\WindowsApps\`（ACL 不可读，`icacls` 报 Access denied）
- **推测**（未证实）：其 AppContainer 层在嵌套沙箱时可能导致权限边界异常
- **反证**：实测它在受限令牌下**正常执行**；装上之后调用**零失败**
- **目前结论**：只有"**诊断不便**"这一条实际影响；功能异常**没有证据**
- 详见 [核对故障报告的归因](../03-可复用工作流/核对故障报告的归因.md)

### 4. WSL 是否值得装

- **现状**：`wsl.exe` 存在，但**功能未启用、无发行版**；虚拟化前置条件（BIOS 虚拟化 / SLAT）通常已满足
- **判断**：优先级**低于**换 PowerShell 7 —— 它是补 Linux 工具链（ffmpeg/pandoc/docker），
  **不是"shell 难用"的解**
- **代价**：需管理员权限 + 一次重启；发行版占数 GB
