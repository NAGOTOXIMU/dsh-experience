## 1. 关于文件与记忆的分层

| 偏好 | 用户原话要点 |
|---|---|
| **讨厌一份文件里混着多种性质的内容** | "有些文档是全局的，有些文档是限制的，都应当分门别类的整理好" |
| **`AGENTS.md` 必须短，不要冗长杂乱** | "注意不要让 AGENTS.md 过于冗长杂乱（这是之前的提出来的问题）" |
| **要能分清哪个文件是干什么的** | "我不太清楚那个文件到底是干什么用的" |

**落地方式**（已实施）：

| 文件 | 性质 | 何时读 |
|---|---|---|
| `~/.dsh/AGENTS.md` | 必须无条件遵守的规则 | 每次会话自动注入（**刻意压短**，约 13 KB） |
| `~/.dsh/DSH-ENV.md` | 事实与操作手册 | 排查/改配置/装插件前按需读 |
| `~/.dsh/DSH-CAPABILITIES.md` | 能力台账 | 问能力边界时 |
| `~/.dsh/skills/*` | 某类任务的操作步骤 | 按需 `skill` 加载 |

> **教训**：`AGENTS.md` 曾膨胀到 23 KB，里面混着规则、路径、踩坑、命令模板。
> 结果是**每次会话都付这份 token 成本，还把真正重要的规则稀释掉**。
> 拆成三份后降到约 13 KB。

## 2. 关于磁盘与产出

- 磁盘容量有限 → 一次性产物推送远端后**清理本地**
- 但**经验正文 / 常驻工具不要清理**（要持续使用）
- 归档产物必须**写明"这是什么、能不能删"**，不要让用户猜

## 3. 关于助手的行为期望

| 期望 | 说明 |
|---|---|
| **尽可能独立完成** | 不要频繁把决定推回给用户 |
| **不会的要会去学** | 遇到不会的，主动去查/去找工具，而不是卡住 |
| **出问题要自己察觉、报告、修** | 见 `capability-gap-handling` skill |
| **主动去 GitHub 找插件/skill 推荐** | 而不是等用户提 |
| **追求能力上限** | 愿意装插件、加 skill、调配置 |
| **但破坏性操作仍需先确认** | 删除、卸载、推远端必须先问 |

## 4. 关于子代理（硬约束）

**启动任何子代理（`subagent` / `subagent_fork` / `workflow` 的 `agent()`）之前，
必须先询问用户并等待明确同意** —— 无论当前权限如何。

具体：要说明**要开几个、各自做什么、预计耗时与成本**，然后停下等答复。
**用户某次的同意仅对那一次有效**，不会自动延续。

> 这条在 `~/.dsh/AGENTS.md` §1，标为最高优先级。

## 5. 关于语言

- **思维链（推理过程）必须用中文**，技术名词/路径/报错原文保持原样不翻译。
- 最终答复用中文。

## 6. 关于经验沉淀（用户主动提议的机制）

用户提出：把每次协作的经验、用户要求、修正过程整理成**成长报告**存进私有仓库，
以便日后调试其他 harness 或帮助别人时直接取用，甚至可以把单篇发给别人。

**已建**：`github.com/NAGOTOXIMU/dsh-experience`（私有）
**格式约定**：见 `~/.dsh/DSH-ENV.md` §7 与 `capability-gap-handling` skill §9
**铁律**：每条必须标证据等级（`已证实` / `已推翻` / `未证实`）
